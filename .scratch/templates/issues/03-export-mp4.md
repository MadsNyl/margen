# 03: Export an Animation video to MP4

**What to build:** An Export button in the top bar of an Animation video. Margen steps the clock frame by frame at 30 fps at the frame size, captures each frame and encodes H.264 MP4 with a bundled ffmpeg, then saves through a Save dialog opening in the Project folder. Show progress and allow cancel.

**Blocked by:** 02

**Status:** done

Spec: `.scratch/templates/spec.md` (Export). Bundling precedent: `build/dugite-git.mjs`, `electron-builder.yml`. Export logic is a framework-free module under `src/main/` taking the frame source and ffmpeg path as arguments.

- [x] Frame-exact capture via the clock from ticket 02, at the frame size regardless of window size
- [x] Progress and cancel; the partial file is removed on cancel

## Notes from ticket 03

**ffmpeg and its licence.** Margen builds its own ffmpeg: **FFmpeg 9.0.2, LGPL-2.1-or-later only**, from the official release tarball (`https://ffmpeg.org/releases/ffmpeg-9.0.2.tar.xz`, pinned by sha256, which I checked against the release's signature, key `FCF986EA…D67658D8`). Why not download a build: ffmpeg.org's macOS builds (evermeet, Martin Riedl) are GPL, because they include x264; npm's `ffmpeg-static` / `@ffmpeg-installer` are GPL too; the LGPL macOS builds that exist are binaries from small, unvetted GitHub repos. Building from source gives an LGPL binary we can audit and a minimal one (3.4 MB). H.264 comes from Apple's **VideoToolbox** (`h264_videotoolbox`, `-allow_sw 1` falls back to Apple's software encoder where there's no hardware one, as in a VM), so there's no x264 and nothing GPL. Configure is `--disable-everything --disable-autodetect`, plus only rawvideo/WAV in, `h264_videotoolbox` and `aac` out, the MP4 muxer, file/pipe, and a few filters (scale, format, aresample, apad…). It has no `--enable-gpl`, `--enable-version3` or `--enable-nonfree`, and `build/ffmpeg.mjs` fails the build if `config.mak` shows any of them. The binary only links system frameworks. `COPYING.LGPLv2.1` and a `README.txt` (version, source URL and sha256, the exact configure line) ship beside it, which covers the LGPL's notice and source-offer duties for an unmodified build. ffmpeg runs as a separate process, so Margen's MIT code isn't affected.

**Build and packaging** (`build/ffmpeg.mjs`): `ensureFfmpeg(arch)` compiles with the system clang (Xcode CLT; no nasm, x64 has `--disable-x86asm` and is cross-compiled with `-arch x86_64`). It takes about 30 s per arch, and results are cached in `$TMPDIR/margen-ffmpeg/<version>-<arch>-<config hash>/`, then copied to `vendor/ffmpeg/<arch>/` (gitignored). `postinstall` runs it for the machine's arch; `build/before-pack.mjs` (beforePack now runs dugite's hook and this one) runs it for the arch being packed. `electron-builder.yml` `extraResources` copies `vendor/ffmpeg/${arch}` to `Contents/Resources/ffmpeg/`, outside the asar. Main finds it at `process.resourcesPath/ffmpeg/ffmpeg` when packaged, `vendor/ffmpeg/<process.arch>/ffmpeg` otherwise. I checked `electron-builder --mac dir --arm64 --x64` (unsigned): both packed apps exported a 9:16 video, x64 under Rosetta. Signing and notarizing haven't been tried; electron-builder signs every Mach-O in the bundle with the hardened runtime, and ffmpeg needs no entitlements.

**Module** `src/main/video/export.ts`: `exportVideo({ ffmpeg, frames, output, audio?, onProgress?, signal? })`. `VideoFrames` is `{ length (s), size {width,height} (CSS px), frame(time) → { width, height, data: BGRA }, close() }`. There are `frameCount(length)` = ceil(length × 30), at least 1, frames at `n / 30`, and `-t frames/30`. Frames may come at any constant size (a 2× capture); ffmpeg scales them to `size` (rounded to even) with lanczos, into yuv420p with BT.709 tags, at about 0.15 bits per pixel (~9 Mbit/s at 1080p), High profile, `+faststart`. The MP4 is written to `<output>.partial` and renamed when ffmpeg exits 0. On cancel (`signal`), a failed frame or an ffmpeg error, ffmpeg is killed, the partial file is removed and `frames.close()` runs.

**Audio, for ticket 05:** pass `audio: <path to a WAV>`. It plays from 0 and is padded with silence (`apad`) or cut to the video's length, then encoded as AAC 192k (`-map 1:a`). The bundled ffmpeg decodes WAV only (pcm_s16le/s24le/f32le, which covers `speak()`'s mono 16-bit at the model's rate, since `aresample` converts) and has no `amix`/`adelay`. So ticket 05 should mix the narration lines into one WAV in JS at their `start` offsets (it has `voices/wav.ts`) and pass that. Otherwise, add filters to `COMPONENTS` in `build/ffmpeg.mjs` (the config hash changes, so every machine rebuilds). At the host level, `exportOpenVideo` in `host/index.ts` is where the narration WAV goes into `exportVideo`.

**Frames in the app** (`src/main/video-frames.ts`, `openVideoFrames(url, preload)`): a hidden **offscreen** `BrowserWindow` (`offscreen: { deviceScaleFactor: 1 }`, the Document partition, the document preload, sandboxed, muted, no navigation). It is resized to the clock's `frame` once the page answers, so capture is at exactly the frame size whatever the editor window is, and the editor's view and paused time aren't touched (there's nothing to seek back). It has no `<webview>` host, so main sends a new bridge message, `{ type: 'export' }`, after which the document script sends through `ipcRenderer.send` (received on `webContents.ipc`) instead of `sendToHost`. Each frame is a `clock-seek { time, id }`, then `capturePage` once the `clock` answer with that id arrives, then `toBitmap()` (BGRA on the Mac). About 30 ms a frame at 1080p; a 2 s 1080p video exported in about 2.5 s on this Mac. A page with no answer to the first seek within 20 s is "not an Animation video"; each later frame times out after 10 s. **Change to the clock (`src/preload/clock.ts`):** a seek's answer now also waits for `document.fonts.ready`, so a web font's first frame isn't captured in the fallback font.

**Host API:** `video.export() → string | null` checks the marker on disk, rejects for other Documents and while an export runs, and opens the Save dialog at `<Project>/<document name>.mp4` (`pickSaveFile`, `MARGEN_SAVE_FILE` in Seam 2). It resolves to the saved path, or `null` when the dialog or the export was cancelled. `video.cancelExport()`. Event `video.exportProgress { frame, frames }` (in `FORWARDED_EVENTS`). Closing the Document cancels a running export. `createHost({ video: { ffmpeg, frames: (url) => Promise<VideoFrames> }, pickSaveFile })`; without them, export rejects.

**Renderer:** `editor/export.tsx` `ExportButton` sits after the timer in a video's top bar, disabled until the clock has reported. While exporting it turns into "Exporting", a `progressbar` "Export" with the percentage, and "Cancel export". After that a notice says "Exported <file>" (`status`) or "Export failed: …" (`alert`). The icon is Hugeicons `FileExportIcon`.

**Real export on this Mac:** I exported a 2 s 1920×1080 video made from the Template's starting file with a heading fade and a bar growing across the frame. ffprobe gave `h264 High, 1920x1080, yuv420p, bt709, 30/1, nb_read_frames=60, duration=2.000000`. Frames pulled out were exact: at 0.5 s the bar was 480 px (¼ of 1920), and the last frame (59/30 s) was 1888 px.

**Tests:** Seam 1 `test/seam1/video-export.test.ts` runs a fake `VideoFrames` (solid colours at 2×) through the real `vendor/ffmpeg`, skipped where it isn't built. It covers frame count, duration and size, a length between frames, progress, cancel removing the partial, the Save dialog cancelled, a failed frame, only Animation videos, and the audio track padded or cut. `test/seam1/mp4.ts` reads the MP4's boxes itself (track handler, codec, sample count, duration, size), so the tests don't trust ffmpeg about its own output. Seam 2 `e2e/export.spec.ts` exports a 1280×720 video (bigger than the editor shows it) through the real app and checks the file.
