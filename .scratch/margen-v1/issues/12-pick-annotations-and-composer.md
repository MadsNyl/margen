# 12: Pick Annotations and the Composer

**What to build:** The floating toolbar with Browse and Pick (V, P; Esc back to Browse). In Pick, hovering highlights an element with its selector and the page's own clicks are blocked; clicking makes a numbered Pick Annotation and opens its comment box (↵ sends, ⌘↵ adds to the message, Esc discards). Pending Annotations show as markers on the Document and matching chips in the Composer (click to reopen, × to remove). Sending puts the Annotations into the Turn with their descriptors and Viewport width; markers fade and thumbnails stay in the chat (user stories 37–44, 56–67).

## Notes from ticket 12 (for 13, 14 and later)

- **Annotation model:** unchanged from `src/shared/agent.ts` (`PickAnnotation` = base + `ElementDescriptor`, `DrawAnnotation` with `targets: ElementDescriptor[]`, `screenshot`/`crop` data URLs). The renderer builds the descriptor from the page script's `pick` message; the host fills `lines` in `session.send` (`locateAnnotations`, `src/main/turns/index.ts`), for picks and for every Draw target, so the stored user entry and what the Agent gets match.
- **Source lines:** `src/main/turns/locate.ts` parses the Document with `parse5` (new dependency) and matches the selector against it, first with classes, then without (scripts change classes). Zero or several matches: no `lines`. The selector grammar is what `selectorOf` in `src/preload/elements.ts` writes: `tag`, `#id`, `.class` (up to two), `:nth-of-type(n)`, joined by ` > `. It climbs until unique with at least the parent, or stops at an id or `<body>`. Change both together.
- **Prompt:** every Turn names the open Document (the follow-up from 15), with or without Annotations. `buildPrompt(turn, document)` in `src/main/turns/prompt.ts` returns provider-neutral parts (text, PNG images); the Claude adapter turns them into SDK content (a plain string when there's no image). `StartSessionOptions.document` is new, passed by `startDocumentSession`. Draw annotations already get a basic block (bounding box, targets) and their `screenshot`/`crop` go along as images. **14:** rewrite `describeAnnotation`'s draw branch and add the "a drawing may point at something or show something to add" line; the test is in `test/seam1/claude-turn.test.ts` ("a Turn with Annotations"). The CLI's temp-folder `Read` of attached images is **not** filtered yet. Do it in `claude/messages.ts` once images are actually sent (14).
- **Bridge** (`src/shared/document-bridge.ts`): `ToDocument` `mode` (`Mode` = browse | pick | draw) and `track { elements: {id, selector}[] }` (replaces the followed set; the script holds the element while the page lives, and finds it again by selector after a reload or if it's removed). `FromDocument` `hover { target: {selector, rect} | null }`, `pick { id, element, rect }` (the script starts following `id` at once), `rects { [id]: Box | null }` (sent from a rAF loop only when something changed, while anything is followed or hovered), and `key` (V/P/D/Esc pressed while the page has focus and the user isn't typing in it). All boxes are in the guest's CSS px relative to its viewport = the frame, so the overlay uses them as they come.
- **Page script** (`src/preload/document.ts`): capture-phase listeners on `window` block click, dblclick, auxclick, contextmenu, mouse/pointer down/up, touchstart/end, dragstart and submit in any Mode but Browse (Draw included already). Pick picks on `click`. A constructed stylesheet in `document.adoptedStyleSheets` forces a plain cursor outside Browse; nothing is written into the page. Element helpers (`describeElement`, `selectorOf`, `rectOf`, `findElement`) are in `src/preload/elements.ts` for 13/14.
- **13 (arrow keys):** in the script, handle arrows/↵ in the keydown capture listener while `mode === 'pick'` (the editor's window doesn't see keys while the webview has focus). Set `hovered` and call `watch()`; ↵ calls `pick(hovered)`. Add a `byKey` flag to the `hover` message for the key guide and `.hl.kbd` ring, and scroll with `element.scrollIntoView({ block: 'nearest' })`. While the comment box or Composer has focus the keys are in the renderer, so they never reach the script (story 13.3 for free); arrows pressed in the renderer while the Document isn't focused would need forwarding over the bridge (a new `ToDocument` `key`).
- **14 (Draw):** add the Draw button to `TOOLS` in `editor/Toolbar.tsx` and `d` to `MODES` in `editor/ModeShortcuts.tsx` (the script already sends `d`). `PickLayer` (`editor/PickLayer.tsx`) follows Draw targets as `<id>/<i>` (see `tracked()`) and anchors a drawing on its first target; give `anchorOf` the strokes' box for drawings with no target, with strokes kept in page coordinates (add `scroll` from the bridge). The canvas goes in the frame next to `PickLayer` (EditorScreen marks the spot). `draft.add(id, annotation)` numbers and opens it; to add strokes to the open drawing, add an `update(id, annotation)` to the draft. The comment box (`CommentBox`) already switches its title to "Drawing"; its hint and placeholder are Pick's.
- **Draft** (`editor/draft.tsx`, `useDraft()`): text, pending Annotations (`{ id, annotation }`), the open one, the fading ones (650 ms) and `lastSent` (for the glow). It also holds the model choice (ticket 10's `ModelChoice`), because a Turn sent from the comment box needs it too. It resets when the Document changes. `send()` clears the draft and calls `session.send`; if the host refuses, text and Annotations come back. Numbers count up per Document view (from 1 again after switching Documents or reopening), not per Session.
- **Glow (story 32):** after each reload the elements of the last sent Turn's Annotations get a green 1.4 s pulse (`[data-glow]`), found by selector. An element whose selector the edit changed doesn't glow.
- **Esc:** the comment box takes its Esc (discard, `preventDefault`), so ChatPanel's Esc doesn't also stop a Turn. With no box open, Esc leaves Pick *and* still stops a running Turn (the prototype only stops). An Esc pressed while the Document has focus comes over the bridge, so it never stops a Turn.
- **Seam 2:** `launchApp` now writes the fake's received TurnInputs to a file; `sentTurns()` reads them (`FakeAgentScript.sentFile`). `e2e/pick.spec.ts` clicks inside the Document with real mouse input at `frame box + guest rect` (`centerOf`), which 13/14 can reuse for hover and strokes.
- **15's @ picker:** its options set the highlight on `mousemove` with real movement instead of `mouseenter`. The list opening under a still cursor used to undo ↓, and `e2e/chat-bar.spec.ts` failed most runs on `margen-v1`.
- **Seam 2 timing:** a just-loaded Document view sometimes loses the very first mouse event (click or move), and a new Mode reaches the page a moment after the toolbar shows it. `e2e/pick.spec.ts` retries the first click/hover with `toPass` and waits for the page's own cursor (`pageInMode`: a plain arrow in Pick) before pointing. 13/14 should do the same.
